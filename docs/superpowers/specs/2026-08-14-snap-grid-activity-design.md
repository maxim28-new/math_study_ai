# 小欧 H5 可动手学具（snap_grid）设计

日期：2026-08-14  
状态：已实现  
产品：小欧（苏格拉底式数学老师）手机 H5

## 1. 背景与目标

现有 `xiaoou-draw` 只生成静态 SVG。孩子只能看，不能摆；小欧也看不到她摆了什么。

第一期只做一种学具：**吸附格子（`snap_grid`）**——下面一排托盘方块，上面一块格子盘，松手吸附。用它覆盖现在最常见的「3×3 / 9 块 / 再包一圈」课，把「看图」变成「动手」。

成功标准：

- 孩子能用一根手指把方块拖进格子，松手吸住。
- 小欧仍是一问一答、不给答案；学具不对对错做裁判。
- 盘面到达「明显摆完」时，小欧自动接下一问；摆的过程中不插嘴。
- 模型只输出活动 JSON，不输出绘图代码。

## 2. 已锁定的决策

| 项 | 决定 |
|---|---|
| 平台 | 先做手机 H5；微信小程序可动手学具以后再说 |
| 交互引擎 | Konva（CDN，无打包器）。不做 DOM 方块方案，避免以后整层扔掉 |
| 聊天壳 | 保持现在的原生 JS H5，不为此改 React |
| 几何引擎 | 不上 JSXGraph；尺规以后作为另一种活动类型再嵌 |
| 沙盘 | 不嵌 Polypad / GeoGebra；不做空白画布 |
| 回传策略 | **方案 C**：平时不报；只有进入里程碑状态才自动发给小欧 |
| 静态图 | 保留。只看不玩的回合继续用现有 SVG |
| 小程序 | 本期零改动。活动规则写成无 Konva 的纯函数，方便以后另写 Canvas 绘制层 |

## 3. 架构

```text
模型 ──xiaoou-draw JSON──► 前端分流
                              ├─ 旧 type（dots / square_* / numberline / bars）→ 静态 SVG
                              └─ type: snap_grid → 活动控制器 → Konva 舞台
                                                                  │
                                        松手（不发模型）          │
                                        进入里程碑（防抖后） ─────┴──► 一条短状态消息 → /api/chat
                                        孩子自己说话 ──附带盘面快照──► /api/chat
```

三层必须分开：

1. **协议**：`xiaoou-draw` JSON（模型可写、前端可校验）。
2. **规则**：吸附、计数、里程碑判定——纯 JS，不依赖 Konva、不依赖 DOM。
3. **绘制**：Konva Stage 只负责画、拖、命中。

以后小程序只替换第 3 层。聊天壳（`web/app.js`）只负责挂载、冻结、把里程碑送进现有 `streamAssistant`。

无打包器：Konva 与活动脚本用 `<script>` 加载，命名空间 `window.XiaoouActivity`，和现在的 KaTeX 一样走 CDN。

## 4. 活动 JSON（第一期只这一种）

沿用现有字段名 `type`，新增一种：

```json
{
  "type": "snap_grid",
  "cols": 3,
  "rows": 3,
  "tray": 9,
  "goal": "fill",
  "caption": "把方块放进格子里试试"
}
```

| 字段 | 规则 |
|---|---|
| `type` | 必须是 `"snap_grid"` |
| `cols`, `rows` | 整数，1–8，缺省 3 |
| `tray` | 托盘里可拖的方块数，0–64，缺省 `cols * rows` |
| `goal` | 第一期只认 `"fill"`（铺满格子）。未知值当 `"fill"` |
| `caption` | 可选，图下说明。**不得写出答案**（与现有画图规则相同） |
| 其它字段 | 忽略 |

校验失败（不是对象、缺 `type`、数字非法）则当没有图，不挂舞台。

模型**禁止**输出 Konva/SVG 代码、禁止输出任意多边形路径。只能输出上表字段。

### 4.1 什么时候用 snap_grid，什么时候仍用静态图

| 这一轮在干什么 | 用什么 |
|---|---|
| 请孩子自己摆、数、试「能不能铺满」 | `snap_grid` |
| 只需要看一眼（两个正方形对比、数轴标点、线段图） | 现有静态 `type` |
| 总结规律、已经摆过、只需回顾 | 静态图即可 |

探索平方数时：第一问「这 9 块能不能摆成正方形」用 `snap_grid`；摆完后小欧追问「再包一圈」可再发一个 `cols/rows/tray` 更大的新活动，或发静态 `square_compare` 让她先看。由模型按这一轮的目标选，提示词里写清楚。

## 5. 交互（孩子看到的）

- 聊天泡泡里一块学具：上为格子盘，下为托盘。
- 方块约 ≥ 44px，单指拖；`touch-action: none`，拖时页面不跟着滚。
- 松手吸到最近空格；离格太远或格已占用则弹回托盘。
- 格子里的块可以再拖回托盘或换格。
- 学具**不显示**「对 / 错 / 这是正方形」。没有自动打分。
- 进入里程碑并已发给小欧后，这块学具仍可继续拖（孩子改主意），但同一状态不重复上报（见第 6 节）。

历史消息里的学具全部**冻结**：不能再拖，看起来仍是最后盘面。新的一则小欧消息若带新 `snap_grid`，立刻冻结上一块。从 `localStorage` 恢复会话时，全部冻结（避免一打开就挂着可拖的旧盘）。

一则小欧消息里若出现多段 `xiaoou-draw`，只让**最后一段** `snap_grid` 可拖；其余静态或冻结。一则消息里不要既可拖又要求她同时看两盘棋。

流式输出：围栏未闭合、JSON 还不完整时不挂 Konva；解析成功后再挂。Konva 脚本加载失败时，退回一张静态格子示意图（不可拖），不让整句回复空白。

挂载时记下初始盘面（托盘满、格子空），**不把初始态当成里程碑**。`detectMilestone` 只在孩子一次拖放结算之后调用。

## 6. 回传策略（方案 C）

### 6.1 盘面状态（规则层的唯一数据结构）

```json
{
  "type": "snap_grid",
  "cols": 3,
  "rows": 3,
  "filled": 9,
  "empty": 0,
  "tray_left": 0,
  "goal": "fill"
}
```

`filled + empty === cols * rows`。`tray_left` 是还在托盘里的块数。

### 6.2 什么叫里程碑（进入时触发，边沿触发）

只在一次 `pointerup`（吸附结算之后）比较「上一快照 → 当前快照」：

| 事件 `event` | 条件 |
|---|---|
| `board_full` | `empty` 从 >0 变成 0（格子铺满，托盘是否还有剩都算） |
| `tiles_exhausted` | `tray_left` 从 >0 变成 0，且 `empty > 0`（块用完但格子还有洞） |

不触发：

- 每一次松手、每一次换格
- 放第 1 块到第 n−1 块
- 从「已铺满」拿掉一块（离开里程碑不发消息）
- 同一块活动上，同一种 `event` 已经发过，且当前仍处于该状态

若铺满后又拆开、再铺满：第二次进入 `board_full` 再发一次（孩子改完又摆好，小欧可以接）。

防抖：进入里程碑后 **400ms 内**若盘面又离开该状态，取消发送（避免刚铺满立刻拿起来仍去打断她）。

发送时若 `/api/chat` 正在流式回复：等当前流结束再发；排队最多 **1 条**（只保留最新盘面）。

### 6.3 发给模型的文本（对话历史里是 user）

界面上不要出现 JSON。孩子气泡里只显示一句短状态，例如「摆好了：9 个格子都满了」或「方块用完了，格子还空着」。

写入 `state.messages`、真正发给模型的是固定模板（中文，便于小欧读）：

```text
（孩子在学具上摆完了一步，这不是她打的字）
学具：snap_grid
格子：3×3
已放：9
空格：0
托盘剩余：0
节点：board_full
```

小欧根据这几行追问，**仍然不说答案**。前端不根据 `board_full` 弹出「你成功了」。

### 6.4 孩子自己说话时

现有发送路径不变。若当时有一块**未冻结**的 `snap_grid`，在她的话后面附上同一套盘面快照（同样用「这不是她打的字」标记）。这样她说「我摆好了」时，小欧看得到其实是 7/9，而不是只听到空话。这不属于「每次松手上报」。

## 7. 提示词

改 `server/tutor.py` 的 `DRAWING_GUIDE`：

- 增加 `snap_grid` 格式与字段表。
- 写明：需要孩子动手摆时必须用 `snap_grid`，不要用点阵 SVG 代替。
- 写明：会收到「孩子在学具上摆完了一步」这类 user 消息；只根据盘面问下一句；不要祝贺「成功」，不要把 `board_full` 直接说成「这就是正方形 / 一共 9 块」。
- 继续禁止 caption 泄露答案。
- 静态六种 `type` 全部保留。

不改后端 `/api/chat` 协议：里程碑就是多一条普通 user 消息。

## 8. 文件与职责

| 路径 | 职责 |
|---|---|
| `web/activity/state.js` | 校验 JSON；从盘面算 `filled/empty/tray_left`；`detectMilestone(prev, next)` |
| `web/activity/snap-grid.js` | Konva 绘制与拖拽；调用 state；冻结 / 销毁 |
| `web/app.js` | 分流渲染；挂载到气泡；防抖发送；历史冻结；说话时附带快照 |
| `web/index.html` | 脚本顺序：Konva CDN → `state.js` → `snap-grid.js` → `app.js`；全部带 cache-bust |
| `web/styles.css` | 学具在气泡里的尺寸、托盘区、冻结态 |
| `server/tutor.py` | `DRAWING_GUIDE` |
| `tests/activity_state_test.js` | 用 Node 跑 `detectMilestone` 与 JSON 校验，不加载 Konva；由现有 unittest 调用 |
| `tests/test_frontend_regressions.py` | 断言引入了 Konva、`snap_grid`、活动脚本 cache-bust |

`state.js` 不得 `new Konva`。这样规则可以在无浏览器环境测试，以后小程序也能复用判定。

## 9. 错误处理

- JSON 坏了：当没有图。
- `cols/rows/tray` 越界：clamp 到第 4 节范围。
- Konva 未加载：静态回退。
- 里程碑发送失败：学具保持可玩，不弹技术错误给孩子；控制台记一条即可。
- 旧会话里没有活动脚本时的历史：按现在的 Markdown/SVG 路径渲染，忽略未知 `type`。

## 10. 测试要点

规则层（必须自动化）：

- `3×3`、`tray=9`：放满 9 格 → 一次 `board_full`；再拿掉一块 → 无事件；再放回 → 第二次 `board_full`。
- 放满后 400ms 防抖属于 UI，规则层只测边沿：`detectMilestone` 无时钟。
- `tray=7`、`3×3`：7 块用完且仍有空格 → `tiles_exhausted`；此时再铺满不了，不出现 `board_full`。
- `tray=12`、`3×3`：9 格满、托盘剩 3 → `board_full`，不是 `tiles_exhausted`。
- 非法 JSON / 缺 type / 行列为 0 → 校验失败。

回归：

- 旧六种静态图仍渲染。
- `index.html` 对 css/js/activity 带 `?v=`。
- `DRAWING_GUIDE` 含 `snap_grid` 与里程碑说明。

手动（实现后在手机 Chrome）：

- 单指拖、吸附、弹回、页面不滚。
- 铺满后约 0.4s 小欧才开口；铺满立刻拆开则不开口。
- 翻上看旧图不能拖。

## 11. 明确不做（第一期）

- React / 打包器 / JSXGraph / Polypad
- `dots_play`、分数条、天平、尺规
- 学具内自动判定「这是正方形」
- 每次 `pointermove` / `pointerup` 打模型
- 改微信小程序
- 发现相册 / 仪式感截图（以后的产品线，不堵在第一期）

## 12. 以后怎么加，而不换引擎

新 `type`（点亮点阵、分数条）= 新的绘制模块 + 同一套「状态 / 里程碑 / 挂载」。尺规 = 另挂 JSXGraph 的一种 `type`。小程序 = 复用 `state.js`，重写绘制。聊天壳继续不知道 Konva 细节。
