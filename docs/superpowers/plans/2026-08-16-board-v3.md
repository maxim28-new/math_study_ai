# 数学画板 V3

## 目标

探索模式只允许题卡驱动画板。出题作者描述数学模型、孩子要做的任务和揭示策略，
服务端验证后再交给前端确定性渲染。陪练只说话和读取盘面，不再生成画图 JSON。

## 协议

所有新题卡必须携带：

```json
{
  "board": {
    "schema": 3,
    "kind": "layer_sum",
    "model": {},
    "task": {},
    "view": {}
  }
}
```

- `model`：题目中客观存在的数学对象和关系；
- `task`：孩子当前要做什么、回答什么；
- `view`：画板先展示什么、隐藏什么；
- `kind`：选择受控活动模板，不包含 DOM、SVG、Canvas 或任意执行步骤。

第一批活动：

- `layer_sum`：观察分层物体并求合计。连续奇数 `1,3,5` 时用 `view.reveal=stepwise`，孩子点「加上下一层」往外圈，围成正方形。
- `path_count`：按允许步长枚举路径；
- `snap_grid`：拖动有限数量方块到格子；
- `static_diagram`：受白名单和逐字段校验的点阵、数轴、线段图等静态模型；
- `geometry_compass`：按步骤完成“两圆交点构造正三角形”的尺规活动。

## 单一来源

1. 作者输出题卡；
2. 服务端将题卡标准化为 V3，未知 `kind`、未知静态图类型或非法参数整卡拒绝；
3. 前端只从 `problemCard.board` 挂载探索画板；
4. 陪练回复只能包含孩子可见文字，不能更新或替换画板；
5. 盘面变化通过确定性的 snapshot 随孩子下一条消息回传。

V1 `diagram` 和 V2 `semantic_board` 只用于读取旧会话，并在边界转换为 V3。新作者提示
不再暴露这两套协议。

## 失败规则

- 作者生成不合法：重试；仍失败时使用同主题、经过测试的种子题；
- 前端收到未知或无法挂载的 V3：显示儿童友好提示，不清空为无说明的白板；
- 陪练违规输出未知画板 JSON：不显示代码、不写入探索历史、不改变当前画板；
- 已经挂载的题卡画板不会被陪练文本或历史恢复逻辑覆盖。

## 兼容与测试

- Python 与 Node 共用 V3 合法/非法 fixture，验证两端标准化结果一致；
- 每种 V3 `kind` 都有协议测试；
- 前端回归覆盖：几何组件加载、未知代码不泄漏、探索模式不再调用文字同步画板；
- 旧 V1/V2 fixture 仅验证可转换，不允许成为新题卡输出。
